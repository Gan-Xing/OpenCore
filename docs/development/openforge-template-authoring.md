# OpenForge Template Authoring

更新时间：2026-06-10

OpenForge V1 template authoring is for generated platform skeletons only. Templates may create or update generated-owned files that contain a valid OpenForge marker. Templates must not write `.env*`, `prisma/schema.prisma`, `prisma/migrations/**`, or human-authored entry files.

## Template Pack

The default template pack is `openforge-default-nest-umi-v1` in `tools/generator/src/templates/default-template-pack.ts`.

It renders:

- NestJS API skeletons under `apps/api/src/modules/generated/**`.
- Umi Max Admin skeletons under `apps/admin/src/pages/Generated/**`.
- SDK generated files under `packages/sdk/src/generated/**`.
- Generated docs under `docs/generated/openforge/**`.
- Prisma model draft and migration hint under `prisma/openforge-drafts/**`.
- Patch-only review plans under `openforge-patches/**`.

## Generated Marker

Every generated-owned file must include:

```text
@generated by OpenForge
templateVersion
schemaHash
moduleCode
artifactKind
generatedAt
```

Review the marker before allowing OpenForge to update an existing file. A generated target without a valid marker is treated as human-authored and must block writes.

## Patch-Only Templates

Patch-only templates produce review markdown. They do not edit the target human file.

Patch-only plans cover:

- `apps/api/src/app/app.module.ts`
- `apps/admin/.umirc.ts`
- `apps/admin/src/access.ts`
- `packages/module-registry/src/modules.ts`
- `packages/sdk/src/index.ts`

## Authoring Rules

- Keep templates deterministic for the same schema/config input.
- Use schema fields, actions, permissions, OpenAPI paths and admin config explicitly.
- Keep repository implementations as placeholders unless a later handoff authorizes real persistence.
- Keep Prisma output as draft/hint only.
- Never emit secrets, env values, credentials or local runtime URLs.
- Do not add CRM, ERP, MES, WMS, mall, payment, member, multitenancy, Knowledge, RAG, Agent or AI workflow templates in V1.

## Verification

Run:

```bash
pnpm openforge:test
pnpm openforge:gate
pnpm format:check
pnpm lint
pnpm typecheck
```

For template changes that affect output, also run:

```bash
pnpm openforge:apply -- --schema tools/generator/examples/core.dict.v1.schema.json --dry-run
```

Then verify no generated output was written unless the task explicitly used `--yes`.
